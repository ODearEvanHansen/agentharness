    第 17 讲 · 推理基础：预填充与解码¶

    KV cache、算力瓶颈与访存瓶颈

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第十七讲，推理基础。从这一讲开始，我们打开推理服务这个黑盒。今天讲推理的基础：预填充与解码，K V cache，以及算力瓶颈和访存瓶颈。作业四也在这一周发布。

    一次请求的两个阶段¶

    预填充一次处理整个提示；解码每次只生成一个 token

    预填充      系统提示 + 工具 + 历史 + 新消息（并行处理）
解码 1     读全部 KV | token 1
解码 2     读全部 KV | token 2
解码 3     读全部 KV | token 3

    一次模型请求分成两个阶段。第一个阶段叫预填充，模型把整个提示，包括系统提示、工具定义和对话历史，一次性并行处理完。第二个阶段叫解码，模型每次只生成一个 token，生成完再把它接到后面，继续生成下一个。

    要点

    预填充：一次算很多 token；解码：一个一个地生成

    K V cache：不重复计算历史¶

    注意力需要每个历史 token 的 Key 和 Value

    • 每生成一个新 token，都要和所有历史 token 做注意力
    • 把历史 token 的 K、V 存下来，下一步直接复用
    • 代价：KV cache 随上下文长度和并发数线性增长
    • agent 的上下文动辄上万 token，KV cache 很占内存

    解码时，每个新 token 都要和所有历史 token 做注意力计算，需要它们的 Key 和 Value。如果每一步都重新算，代价太大。所以推理服务会把历史 token 的 K 和 V 存起来，这就是 K V cache。它是用内存换计算，大小随上下文长度和并发数增长。agent 的上下文动辄上万 token，这块内存非常可观。

    要点

    用内存换计算

    两种瓶颈¶

    预填充：算力瓶颈

    • 很多 token 一起做矩阵乘
    • 读一次权重，算很多次
    • 速度取决于算力

    解码：访存瓶颈

    • 每步只算一个 token
    • 却要把全部权重读一遍
    • 速度取决于内存带宽

    这两个阶段的瓶颈完全不同。预填充时，很多 token 一起做矩阵乘法，权重读一次可以算很多次，瓶颈在算力。解码时，每一步只算一个 token，却要把整个模型的权重从内存里读一遍，瓶颈在内存带宽。所以解码慢，不是算不动，而是数据搬不动。

    要点

    解码慢，不是算不动，而是搬不动

    实测：预填充远快于解码¶

    作业四 E5：llama-bench pp512/tg128，Qwen3-8B，Xeon Gold 6354，-t 16，单位 tok/s

    项目 数值
    Q4 · 预填充 pp512 116.0
    Q4 · 解码 tg128 17.3
    Q8 · 预填充 pp512 61.3
    Q8 · 解码 tg128 10.7

    看一组真实数据。这是作业四实验五的结果，在 Xeon Gold 六三五四 上用十六个线程，跑 Qwen3 八 B 的 Q4 版本，预填充每秒处理约一百一十六个 token，解码每秒只有十七个左右。Q8 版本的权重更大，要搬的数据更多，两个阶段都变慢了。这正好印证了解码是访存瓶颈。

    要点

    每秒处理的 token 数，预填充是解码的好几倍

    这对 agent 意味着什么¶

    • agent 每一步都要预填充越来越长的上下文
    • 能复用前缀，就能省掉大部分预填充（第 20 讲）
    • 多个请求一起解码，可以分摊读权重的开销（第 19 讲）
    • 推测解码、量化、MoE 都在减少每个 token 的搬运（第 22–24 讲）

    这对 agent 意味着什么？agent 每一步都要预填充越来越长的上下文，所以前缀复用非常关键。解码受内存带宽限制，所以把多个请求合在一起解码，可以分摊读权重的开销。后面几讲的批处理、前缀复用、推测解码和量化，全都是从这两种瓶颈出发的。

    要点

    后面几讲的优化，都从这两种瓶颈出发

    作业四发布：DSH-Serve¶

    在自己的机器上把模型跑起来

    • L1：Ollama 接入 DSH，查清一个反常现象
    • L2：llama-server 上做 E1 到 E5 五个实验
    • L3：把本地模型接回 madsLoop 和 DSH
    • 每个实验标注了学完哪一讲再做；不需要 GPU

    作业四这一周发布，每个实验都标注了学完哪一讲再做。第一关，用 Ollama 把本地模型接到 DSH 上，并查清一个反常现象。第二关，在 llama server 上做五个实验。第三关，把本地模型接回你自己的 agent。整个作业不需要 GPU，但想跑三十 B A 三 B 这个 MoE 模型，需要三十二 GB 内存。

    要点

    每个实验：可复现命令 + 原始数据 + 一段解释

    小结¶

    • 请求 = 预填充（算力瓶颈）+ 解码（访存瓶颈）
    • KV cache 用内存换计算
    • 8B Q4：预填充约 116 tok/s，解码约 17 tok/s
    • 作业四发布

    小结一下。一次请求分为预填充和解码，前者受算力限制，后者受内存带宽限制。K V cache 用内存换计算。练习是在你的机器上跑一次 llama bench，看预填充是不是比解码快好几倍，再用内存带宽除以模型大小，估一个解码速度的上限。下一讲，我们讲本地推理入门，动手在本地跑起模型。

    课后练习

    15 分钟：用 llama-bench 测 Qwen3-8B Q4 的 pp512 和 tg128。预期 pp 是 tg 的好几倍；再用 内存带宽 ÷ 5GB 估算 tg 上限，实测应低于它
