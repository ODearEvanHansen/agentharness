    第 24 讲 · MoE：混合专家模型¶

    激活参数和总参数，为什么 30B-A3B 生成快但占内存大

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第二十四讲，我们讲 MoE，也就是混合专家模型。我们要回答一个问题：为什么一个三十 B 的模型，生成速度反而比八 B 的模型快？

    MoE 的结构¶

    每层有很多个前馈“专家”，路由器为每个 token 只挑几个

    token A  路由器 | 专家 2 | 专家 7 | 其余专家不计算
token B  路由器 | 专家 1 | 专家 5 | 其余专家不计算

    MoE 的思路是，把每一层的前馈网络拆成很多个专家。每来一个 token，路由器只挑选其中少数几个专家来计算，其余专家完全不参与。不同的 token 会选到不同的专家。所以模型的总参数很多，但每个 token 实际用到的参数只有一小部分。

    要点

    总参数很多，但每个 token 只激活一小部分

    读懂名字：30B-A3B¶

    Qwen3-Coder-30B-A3B

    • 30B：总参数约 300 亿，决定要占多少内存
    • A3B：每个 token 激活约 30 亿参数，决定每步要算和要读多少
    • DeepSeek-V3 也是 MoE：总参数远大于激活参数
    • 阅读材料：DeepSeek-V3 技术报告中的 MoE 与负载均衡部分

    读懂模型名字很重要。三十 B A 三 B 的意思是，总参数大约三百亿，每个 token 激活大约三十亿。总参数决定了要占多少内存，激活参数决定了每一步要计算和读取多少数据。DeepSeek V3 本身也是 MoE 架构，本讲的阅读材料是它的技术报告，重点看专家路由和负载均衡的设计。

    要点

    总参数看内存，激活参数看速度

    实测：MoE 生成速度约为 8B 的 2 倍¶

    M0 llama-bench pp512/tg64, -t 16；生成速度 tok/s

    项目 数值
    Qwen3-Coder-30B-A3B Q4 35.6
    Qwen3-8B Q4_K_M 18.6
    Qwen3-8B Q8_0 11.7

    来看试做阶段用 llama-bench、十六线程的实测。三十 B A 三 B 的 Q 四版本，生成速度每秒约三十五点六个 token。稠密的八 B 模型 Q 四版本只有十八点六个。MoE 的生成速度差不多是八 B 的两倍。原因和上一讲一样：每个 token 只需读取约三 B 的激活权重，访存量更小。

    要点

    激活 3B 的 MoE，比稠密 8B 生成还快

    代价：内存按总参数算¶

    M0 报告，Q4 权重文件大小（GB）

    项目 数值
    Qwen3-Coder-30B-A3B Q4 18.6 GB
    Qwen3-8B Q4_K_M 5.0 GB

    但是代价也很明显。三十 B A 三 B 的 Q 四权重文件有十八点六 G 字节，而八 B 只有五 G 字节。运行时加上 K V cache，在三万两千 token 的上下文下，常驻内存大约二十八 G 字节。所以这门课推荐三十二 G 字节内存的机器。

    要点

    运行时 RSS 约 28GB（32k 上下文），需要 32GB 内存

    为什么不能只加载激活的那 3B¶

    作业四 E5 必答题的思路

    • 每个 token 选中的专家都不一样，事先无法知道
    • 所有专家都必须常驻内存，否则要频繁从磁盘换入
    • 所以：速度看激活参数，内存看总参数
    • 对 agent 的意义：32GB 机器上能跑能用工具的本地模型

    为什么不能只加载激活的那三 B 呢？因为每个 token 选中的专家都不一样，事先无法预知，所有专家都必须常驻内存，否则就要频繁从磁盘换入，速度会崩溃。这也是作业四的一道必答题。对我们的 agent 来说，MoE 的意义在于：在一台三十二 G 字节内存的机器上，可以跑一个又快、又会用工具的本地模型。

    要点

    MoE 把“算得快”和“装得下”拆成了两个问题

    回到 agent：课程小题解题数¶

    M0 报告，本地模型接入 agent，8 道小题

    项目 数值
    Qwen3-Coder-30B-A3B Q4 8 / 8
    Qwen3-8B Q4 4 / 8
    Qwen3-0.6B Q8 0 / 8

    最后回到 agent。试做阶段把本地模型接入 agent，跑八道课程小题。三十 B A 三 B 全部解出，八 B 只解了四道，而且思考链太长、又慢又不稳定，零点六 B 一道也没解出，只适合当推测解码的草稿模型。

    要点

    30B-A3B 可用；8B 慢且不稳定；0.6B 只适合当草稿模型

    小结¶

    • MoE：路由器为每个 token 只挑少数专家
    • 30B-A3B：总参数看内存，激活参数看速度
    • 实测生成 35.6 tok/s，约为 8B 的 2 倍；权重 18.6GB
    • 32GB 机器上可用的本地 agent 模型

    小结一下。MoE 为每个 token 只激活少数专家，所以生成快，但所有专家都要装进内存。练习是用上一讲的带宽算法，验证速度看的是激活参数。作业四在本周截止。下一讲，我们进入全栈部分：多模型路由。

    课后练习

    算 30B-A3B 的 速度×读取量：按全部 18.6GB 是 662 GB/s，按激活约 1.9GB 是 68 GB/s。预期只有后者接近上讲的约 90 GB/s
