    第 1 讲 · 课程导论：agent 系统是什么¶

    模型 + 循环 + 工具，以及为什么必须隔离

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第一讲，欢迎来到 Agent Harness 公开课。这一讲回答三个问题：agent 系统是什么，这门课怎么学，以及为什么从第一天起就要重视安全。本视频由程序合成，配音来自 DeepSeek 语音合成，演示数据都来自真实运行。

    agent = 模型 + 循环 + 工具¶

    模型负责决定下一步做什么，循环负责把结果喂回去，工具负责真正动手

    第 1 步    用户任务 | 模型思考 | 调用 bash | 工具结果
第 2 步    …之前全部 | 模型思考 | 编辑文件 | 工具结果
第 3 步    …之前全部 | 模型思考 | 运行测试 | done

    一个编码 agent 的结构其实很简单。用户给出任务，模型思考之后，选择调用一个工具，比如执行一条 bash 命令。工具的结果被追加回对话，再交给模型决定下一步。如此循环，直到模型认为任务完成。模型、循环、工具，这就是 agent 的全部骨架。

    要点

    agent：在循环里反复调用模型，执行它选的工具

    这门课的路线：自上而下¶

    参考哈佛 CS2680 的结构，全部换成 DeepSeek 生态

    • 作业一 观察：做一个网页，实时看清 agent 每一步的上下文、工具调用和成本
    • 作业二 从零实现：用约 110 行 Python 写一个能解 SWE-bench 的 agent loop
    • 作业三 优化：在 DeepSeek Harness 上用配置和插件，让 agent 又好又省
    • 作业四 本地推理：在自己机器上部署模型，做批处理、前缀复用、推测解码实验
    • 作业五 全栈：云端模型与本地模型混合路由，三项指标一起优化

    这门课的路线是自上而下。作业一，你先做一个观察工具，看清 agent 每一步在做什么、花了多少钱。作业二，从零写一个一百一十行左右的 agent loop，去解真实的 SWE bench 题目。作业三，在 DeepSeek Harness 上优化 agent。作业四，深入到推理服务，在自己的机器上部署模型。作业五，把 agent 和推理服务放在一起做全栈优化。

    要点

    先看清，再动手，再优化，最后打通推理服务

    先给你一个直觉：真实的 agent 有多强、多贵¶

    试做阶段（M0）实测，deepseek-flash，SWE-bench Verified

    项目 数值
    自写 loop · 原 20 题 18 / 20
    DSH · 原 20 题 17 / 20
    自写 loop · 难题集 10 / 20
    DSH · 难题集 8 / 20

    先给你一个直觉。开课前，课程团队把所有作业自己试做了一遍，这个阶段叫试做阶段，代号 M 零，后面的很多数据都来自它。试做阶段用 deepseek flash 实测：一个一百一十行左右的自写 loop，在二十道 SWE bench 题上解决了十八道，工业级的 DSH 解决了十七道，每道题大约两美分。换成更难的难题集，两者分别降到十道和八道，每题大约四美分。简单的 loop 已经很强，但想在难题上更进一步，就需要这门课讲的工程手段。

    要点

    原 20 题约 2 美分/题，难题集约 4 美分/题

    安全：agent 会在你的机器上执行命令¶

    这是本课最重要的一条纪律

    • 误操作：模型可能删除文件、改坏配置，甚至执行你没想到的命令
    • 泄露：API key 写进仓库、打印到日志，或被 agent 读出来发给外部
    • 提示注入：题目、网页或代码注释里藏着指令，诱导 agent 越权
    • 对策：作业都在 Docker 容器里跑；出网只放行 DeepSeek API；key 只走环境变量

    接下来讲安全，这是本课最重要的一条纪律。agent 会在你的机器上执行真实的命令。它可能误删文件，可能把 API key 打印出来，也可能被题目里藏着的恶意指令诱导。所以课程的所有作业都在 Docker 容器里运行，容器的网络只放行 DeepSeek 的 API，key 只通过环境变量传入，永远不要提交进仓库。白名单能防什么、防不住什么，第八讲会细讲。

    要点

    隔离不是可选项：作业都在容器里跑，出网走白名单

    隐私：DSH 默认会上传会话日志¶

    课程配置 infra/course.patch.yml 默认关闭

    • DSH 自带 session-log-deepseek 插件，会把会话日志随请求发给 DeepSeek
    • 课程统一使用补丁：session-log-deepseek → enabled: false
    • 自己写配置时，第一件事就是检查这个开关

    还有一个隐私问题需要提前说明。DSH 默认会通过一个会话日志插件，把会话日志上传给 DeepSeek。课程提供的配置补丁已经把它关掉了。以后你自己写配置时，第一件事就是检查这个开关。使用任何 harness 之前，都应该先弄清楚它把你的数据发到了哪里。

    要点

    用任何 harness 之前，先弄清它把数据发到了哪里

    你需要准备什么¶

    • x86_64 Linux 或 Windows + WSL2；Docker；内存 16GB 起
    • 作业四 L3 和作业五需要 32GB 内存；不需要 GPU
    • 自己的 DeepSeek API key：原 20 题一轮约 $0.4–0.5（高峰价）
    • 作业三两周调试估计 50–100 元；全课总额待外部试学后校准

    最后看看你需要准备什么。一台 x 八六架构的 Linux 电脑，或者 Windows 加 WSL 二，装好 Docker，内存至少十六个 G；作业四的第三关和作业五需要三十二个 G。不需要 GPU。你还需要自己的 DeepSeek API key。原二十题跑一轮，按高峰价大约零点四到零点五美元；作业三两周调试，估计五十到一百元人民币；全课总额要等外部学员试学之后再校准。作业零本周发布，本周末截止。

    要点

    本周：完成作业零的环境自检（本周末截止）

    小结¶

    • agent = 模型 + 循环 + 工具
    • 课程路线：观察 → 实现 → 优化 → 推理服务 → 全栈
    • 所有作业在容器中运行，出网白名单，key 不进仓库
    • 使用 DSH 先关闭会话日志上传

    小结一下。agent 就是模型、循环和工具。课程从观察开始，一路走到推理服务和全栈优化。所有作业都要在容器里运行，并且关闭会话日志上传。课后花十五分钟运行作业零的自检脚本，直到每一项都通过。下一讲，我们讲 DeepSeek API。

    课后练习

    15 分钟：运行作业零的 selfcheck.py，预期各项检查都显示通过；如有失败，按提示修好再跑一遍
