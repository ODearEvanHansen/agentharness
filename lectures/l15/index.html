    第 15 讲 · 实验方法¶

    对照实验、只改一个变量、重复与方差、统一计价

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第十五讲，实验方法。作业三要你证明某个优化有效，可 agent 的每次运行结果都不一样。怎么让结论站得住？本视频由程序合成，配音来自 DeepSeek 语音合成。

    四条规矩¶

    作业三的方法要求

    • 每个结论都要有对照：和基线比，而不是和印象比
    • 只改一个变量：同一题集、同一模型、同一版本
    • 处理随机性：重复运行，报告方差
    • 成本按官方高峰价统一计算，并单独报告缓存命中率

    先记住四条规矩。第一，每个结论都要有对照，和基线比。第二，每次只改一个变量，题集、模型和版本都保持不变。第三，处理随机性，要重复运行，报告方差。第四，成本统一按官方高峰价计算，并单独报告缓存命中率。

    要点

    没有对照的数字，只是一个数字

    这是作业三裁剪插件的一次真实对照实验的原始记录。每一行是一道题，有耗时、步数和成本。你会发现，题与题之间差别很大，有的题六步就结束，有的要六十多步。所以只看一两道题的变化，几乎说明不了什么。

    要点

    同一批题，耗时和步数差异很大

    这次对照的结论¶

    DSH sdk-minimal，SWE-bench 20 题

    项目 数值
    基线 每题成本 $0.018
    裁剪 每题成本 $0.0170
    基线 命中率 95.8%
    裁剪 命中率 96.1%

    汇总下来，两边都解决了十七道题，每题成本从零点零一八降到零点零一七美元，命中率从百分之九十五点八变成九十六点一。这么小的差异，很可能就是随机波动。正确的结论是：在这个题集上，没有观察到明显效果，而不是插件省了百分之五。

    要点

    解决数都是 17/20：差异小于随机波动，不能下结论

    随机性有多大¶

    排行榜和作业三 L1 的设定

    • 作业三 L1：用自己的 key 复现基线，分析差异是否来自随机性
    • 维护者抽查复现时，解决数允许相差 ±2
    • 环境可复现：GHCR 重新评测与 Docker Hub 结果完全一致
    • 模型输出不可复现：同一配置重跑，步数和路径都会变

    随机性到底有多大？作业三的第一关，就是让你用自己的 key 复现基线，并分析差异是不是来自随机性。排行榜抽查复现时，解决数允许相差正负二。要区分两件事：评测环境是确定的，换镜像源重新评测结果完全一致；但 agent 的行为不是，同一配置重跑，步数和路径都会变。

    要点

    评测环境是确定的，agent 的行为不是

    题集太简单，就测不出差异¶

    M0 实测：自写 loop 与 DSH 的解决数

    项目 数值
    原 20 题 loop 18/20
    原 20 题 DSH 17/20
    困难集 loop 10/20
    困难集 DSH 8/20

    题集的选择也是实验设计的一部分。在原来的二十道题上，两边是十八比十七，已经接近饱和，再好的优化也很难体现。换成困难集后，降到十比八，才拉开了区分度。所以作业三的解决率赛道用的是困难集。

    要点

    接近饱和的题集没有区分度

    计价要统一¶

    tools/usage_cost.py

    • DeepSeek 有高峰价和低峰价：20 题 loop 高峰 $0.51、低峰 $0.26
    • 所有报告统一按高峰价，避免运行时段造成假差异
    • 命中与未命中价格差 50 倍：命中率要单独报告
    • 混合路由时按每次请求实际使用的模型分别计价，本地模型按 $0

    最后是计价。DeepSeek 有高峰价和低峰价，自写 loop 跑二十道题，高峰价是零点五一美元，低峰价只有零点二六。如果两组实验在不同时段跑，账单会差出一倍，这不是优化带来的。所以所有报告统一按高峰价计算，并单独报告命中率。

    要点

    同样的 token，换个时段跑，账单能差一倍

    小结¶

    • 有对照，只改一个变量
    • 重复运行，报告方差
    • 选有区分度的题集
    • 统一按高峰价计价，单独报告命中率

    小结：要有对照，每次只改一个变量；重复运行，报告方差；选有区分度的题集；统一按高峰价计价。课后练习：把二十道题的基线跑两遍，看看两次之间差多少。这个差值，就是你判断优化是否有效的尺子。
