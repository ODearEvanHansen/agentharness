# 期末项目指南

期末项目占证书成绩的 20%。项目可以个人完成，也可以 2–3 人组队。组队时，报告里要写清每个人的分工。

## 选题方向（任选，也可以自拟）

1. **Harness 机制研究**：挑 DSH 的一个机制（例如压缩、子 agent、并行工具调用、request series），设计对照实验量化它的效果，并给出改进方案。
2. **新的评测集**：针对某一类真实任务（比如数据处理脚本、前端小 bug、配置文件排错）构造 20 道以上可自动判分的题目，并用两种以上的 agent 跑出基线。题目要求和作业 2 的社区题库一致。
3. **推理服务优化**：在作业 4 的基础上研究一个具体问题，例如 agent 负载下的前缀复用率、推测解码的草稿模型选择、长上下文的内存与速度取舍。
4. **新插件或新工具**：为 DSH 写一个有实际用途的插件（例如安全审计、成本预算控制、更好的代码搜索），在作业 3 的题集上证明它有效，或者证明它的代价可以接受。
5. **多模型系统**：在作业 5 的基础上设计更好的路由策略，或者研究"不信任本地模型"导致的重复劳动问题。

## 要求

- **可复现**：公开代码仓库，提供一条命令或一个脚本就能重跑主要实验；附上原始数据（jsonl/json）和每次运行的 API 花费。
- **有对照**：每个结论都要有基线对照，并说明重复了几次、方差多大（见第 15 讲"实验方法"）。
- **诚实**：负面结果同样有价值。如果最后的方案没有效果，讲清原因也能拿到好成绩。
- **安全**：所有 agent 实验都在容器里运行，不能在报告或仓库里泄露 API key。
- **预算**：期末项目建议控制在 100 元 API 费用以内（各作业的分项估算见[课程大纲](syllabus.md#预计花费deepseek-api)）。超出预算的大规模实验要在报告里说明理由。

## 提交物

1. 代码仓库链接（包含 README 和复现脚本）；
2. 博客形式的报告（2000–5000 字，中英文均可），发布在任何公开平台；
3. 5 分钟以内的演示视频（可选，**申请证书必须提交**）。

## 评分要点

| 维度 | 权重 |
|---|---|
| 问题是否清楚、是否有价值 | 20% |
| 实验设计与对照 | 30% |
| 可复现性（代码与数据） | 25% |
| 分析与写作 | 25% |

优秀项目会在课程网站上展示，并邀请作者做分享。
