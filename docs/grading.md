# 评分说明

本页说明各作业的评分原则。用于自评：按这里的权重和原则检查自己的作业。

## 权重

与[课程大纲](syllabus.md)一致。

| 部分 | 权重 | 评分方式 |
|---|---|---|
| A0 环境自检 | 0%（完成即可，是后续作业的前提） | [Discussions 打卡](https://github.com/ODearEvanHansen/agentharness/discussions/new?category=show-and-tell&title=%E4%BD%9C%E4%B8%9A%200%20%E6%89%93%E5%8D%A1) |
| A1 DSH-Lens | 10% | `check.py` 50% + 报告 50% |
| A2 miniLoop | 15% | 自动检查 + 源码阅读题 + 对照实验报告 |
| A3 DSH-Opt | 20% | 排行榜提交 + 博客报告（以报告为主） |
| A4 DSH-Serve | 20% | 数据检查 + 报告 |
| A5 DSH-Stack | 15% | `check.py` + 博客报告 |
| 期末项目 | 20% | 见[期末项目指南](project.md#评分要点) |

报告类关卡按 优 / 良 / 及格 / 不及格 四档给分。排行榜名次本身不加分。

## 如何提交与获得反馈

说清楚现状：

- **目前没有人工批改。** 本页的权重和评分原则是公开的标准，供你自评。
- **自动检查**：各作业的 `check.py` 等脚本会告诉你每一关是否通过，这部分是客观的。
- **报告自评**：对照下面的"好报告包含什么"和"常见失分点"给自己的报告定档。想要别人看，可以把报告链接发到 [Discussions 的 Show and tell](https://github.com/ODearEvanHansen/agentharness/discussions/categories/show-and-tell)。
- **排行榜**：作业 3 的结果可以通过 PR 提交到排行榜，流程见[排行榜](leaderboard.md)。PR 会自动校验格式，但不评报告。

## 好报告包含什么

- **可复现的命令和原始数据**：每个数字都能在你提交的 jsonl/json 或日志里找到出处。
- **对照**：一次只改一个变量，说明重复了几次、波动多大。差一两道题通常在随机波动范围内。
- **统一口径**：成本按官方高峰价计算（`tools/usage_cost.py`），缓存命中率单独报告。
- **机制解释**：不只说“变快了 / 变省了”，要说明为什么，并用数据验证你的解释。
- **诚实的负结果**：优化没有效果，讲清原因并有数据支撑，同样可以拿高分。和参考结果不一致时，解释差异来源即可，不必“凑”数字。

## 常见失分点

- 没有对照，或对照组与实验组条件不同；
- 报告里的数字与提交的原始数据对不上；
- 只给现象不给原因，或原因与数据矛盾；
- 用低峰价或其他口径算成本且未说明。

## 学术诚信

- 所有实验数据必须由你自己运行得到。提交课程参考数据（例如 `assignment4/reference/`、`assignment5/baseline/`）的副本或改动版本，视为数据造假，该作业记 0 分。
- 排行榜靠前的提交会被课程团队复现：重算报告数字、核对日志、按你的配置重跑。
- 可以讨论思路、阅读开源代码，但代码和报告须独立完成；引用他人内容请注明出处。
- 不得针对具体题目做特殊处理（例如读取题号走特殊分支）。
- 不要在仓库或报告中泄露 API key。
