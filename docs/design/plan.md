## 1. 学习目标

完成课程的学员应能做到：
1. 读懂编码 agent 的执行轨迹：每一步的上下文、工具调用和 token 成本分别是什么。
2. 从零写出一个能解 SWE-bench 题的最小 agent loop（约 100 行），并说清它和工业级 harness（DSH）的差别。
3. 在 DSH 上通过插件和配置优化 agent，用数据说明每一项优化的收益和代价，重点是成本、前缀缓存和步数。
4. 在自己的机器上部署本地模型，并理解批处理、前缀复用、推测解码、量化对吞吐和延迟的影响。
5. 把 agent 侧和推理服务侧放在一起优化（例如保持前缀稳定、把子任务路由给本地模型），并做出有测量支撑的结论。

## 3. 作业设计

所有作业共用一个课程仓库模板，包含 `assignmentN/`、Docker 镜像、本地评测脚本 `check` 和 `run_all`。每个作业拆成 3–5 个关卡，每个关卡可以单独自动检查。

### A0 环境自检（第 1 周，1–2 小时）
- 运行 `selfcheck.py`，检查操作系统、Docker、网络、key 和 DSH 版本，全部通过即完成。
- 拉取 1 个 SWE-bench 镜像（ACR），跑通 1 道示例题。

### A1 DSH-Lens：观察 agent（4–6 小时）
- 用 Python SDK 驱动 DSH，自己写一个网页，实时展示执行轨迹。M0 已有约 300 行的参考实现，7 项功能全部可行。
- 必做 7 项：提交 prompt、实时轨迹（支持 markdown）、工具结果折叠、单次调用与整轮状态、续聊、成本/耗时/轮数、子 agent 树。
- **加做项（区别于 DSH 自带的 Web 工作台，防止照抄）**：上下文构成图、缓存命中曲线、两次运行的对比视图。
- 说明中必须讲清的两个坑：事件里不带 token 用量，需要读 zstd 格式的会话日志；子 agent 的事件要靠 `subagent.started` 事件来归属。
- 前端依赖要本地打包，不使用 CDN（国内网络考虑）。

### A2 DSH-Loop：自己写 loop（10–12 小时）
- **Part A**：从零写 `madsLoop`（Python，直接调 DeepSeek 的 OpenAI 格式接口，带 bash/read/edit/done 四个工具），在容器里解 SWE-bench 题。参考实现 112 行；M0 中在 20 道 Verified 题上解决 18 道。
  - 说明里要提示：开启思考模式时必须回传 `reasoning_content`。
- **Part B**：阅读 DSH loop 源码并回答对照题（取消处理、并行工具调用的 barrier、request series 与前缀缓存）。源码引用要对应课程锁定的版本 tag。
- **Part C**：在同一批题上和 DSH `sdk-minimal` 做对比，写一页分析：步数、token、成本、解决率，以及工具设计对这些指标的影响。
- **题目贡献**：每位学员提交 2–3 道自建题，审核通过后进入社区题库。

### A3 DSH-Opt：优化竞赛（10–15 小时）
- 学员可以修改 DSH profile（`cordis.patch.yml` 和自写插件）：工具集与工具描述、系统提示、preset（Standard/PTC）、压缩策略、子 agent、`agent/pre-step` 和 `agent/request-error` 两个 hook、推理强度和输出上限。
- 也允许继续使用自己的 A2 loop 参赛。
- **评分改为两个赛道**（因为 M0 显示 flash 在随机 Verified 题上已达 85–90%，单比解决率区分度不够）：
  - **解决率赛道**：使用难题集（见第 4 节），预算设硬上限；
  - **效率赛道**：在不低于基线解决率的前提下，比较每题成本和耗时。M0 基线：DSH 每题 0.12 元 / 中位 55 秒，自写 loop 每题 0.17 元 / 中位 132 秒。
- 单次评测的成本参考：20 题约 2.4–3.4 元（高峰价），低峰时段减半。

### A4 DSH-Serve：本地推理（10–14 小时）
- **入门（1–2 小时，Ollama）**：把本地模型接到 DSH 上。**刻意保留 Ollama 默认约 2k 的上下文**，让学员遇到"agent 只会回答 Hello"的现象，再自己从日志里查出原因：提示词被静默截断。
- **主体（llama-server）**，在 M0 中已验证可行的实验：
  - 批处理：`-np 1` 与 `-np 4` 对比（M0：吞吐提升 1.8 倍）；
  - 前缀复用：`cache_prompt` 开与关（M0：预填充 15 秒对 0.24 秒）；
  - 推测解码：草稿长度对速度的影响（M0：长度 16 时变慢，长度 3 时快 20%）；
  - KV 量化：在 CPU 上更慢且不省内存，作为反直觉案例；
  - 权重量化：Q4 与 Q8 对比；架构：MoE 与稠密模型对比。
- **把本地模型接回 A3 的 agent**，在小题集上测量解决率、成本和速度。
- **模型选型（M0 实测）**：
  - 主力：Qwen3-Coder-30B-A3B Q4（工具调用 8/8，CPU 生成速度约 35 tok/s，需要 32GB 内存）；
  - 16GB 机器：Qwen3-8B Q4，只做推理服务实验，不做 agent 任务；
  - **不使用 DeepSeek 蒸馏模型**：R1-Distill-7B 完全不会调用工具。
- 锁定 llama.cpp commit（参数会改名，例如 `--draft-max` 已改为 `--spec-draft-n-max`）。

### A5 DSH-Stack：全栈（12–18 小时）
- 主 agent 用 DeepSeek API，子 agent 或简单步骤路由给本地模型（通过 DSH 多模型路由），综合优化"解决率 × 成本 × 延迟"。
- 题集：A4 的小题集，加上难题集子集（可选 Terminal-Bench 2.0）。
- 提交物：自愿排行榜成绩 + 博客 + 视频。

### 期末项目
- 产品线或研究线二选一，参照原课程。DSH 特有的推荐方向：给 DSH 贡献插件并提交 PR。

## 6. 学员要求与成本

- **硬件**：
  - 必须：x86_64 Linux（或 Windows + WSL2），16GB 内存，100GB 磁盘，Docker。
  - A4/A5 推荐 32GB 内存。
  - Windows 用户请使用 WSL2。
  - **不支持 macOS**（用户决定）：SWE 镜像只有 x86_64，本地模型实验按 x86 Linux 设计；Mac 用户请使用云主机。
- **API 费用**：每道 SWE 题约 1–2 分钱。全课预计 **100 元以内**，在试做阶段校准后公布。
- **下载量**：每个 SWE 镜像约 3GB（20 题约 60GB），Ollama 1.5GB，30B 模型 19GB。
