    第 18 讲 · 本地推理入门：Ollama 与 llama.cpp¶

    GGUF 格式，以及一次静默截断

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第十八讲，本地推理入门。我们认识 Ollama 和 llama dot cpp 这两个工具，了解 GGUF 格式，再复盘一个课程团队真实踩过的坑：静默截断。本视频由程序合成，配音来自 DeepSeek 语音合成。

    两个工具，两种定位¶

    Ollama

    • 一条命令拉模型、起服务
    • 提供 OpenAI 兼容接口
    • 默认值替你做了很多决定

    llama.cpp / llama-server

    • 参数完全可控
    • 返回 timings，能看清每一步
    • 作业四主体用它

    Ollama 和 llama dot cpp 是两种定位。Ollama 上手最快，一条命令就能拉模型、起服务，还提供 OpenAI 兼容的接口，但它的默认值替你做了很多决定。llama server 的参数完全可控，还会返回详细的耗时统计。所以入门用 Ollama，做实验用 llama server。

    要点

    入门用 Ollama，做实验用 llama-server

    GGUF：一个文件装下整个模型¶

    llama.cpp 使用的模型格式

    • 权重、分词器、对话模板都打包在一个文件里
    • 文件名标明量化档位，例如 Q4_K_M、Q8_0
    • Qwen3-8B：Q4 约 5GB，Q8 约 8.7GB
    • Qwen3-Coder-30B-A3B Q4_K_M：18.6GB

    llama dot cpp 用的模型格式叫 GGUF。权重、分词器和对话模板都打包在一个文件里，文件名会标出量化档位。比如 Qwen3 八 B，Q4 版本约五 G，Q8 版本约八点七 G。课程主力模型 Qwen3 Coder 三十 B A3B 的 Q4 版本是十八点六 G。

    要点

    量化档位决定文件大小，也决定速度和质量

    作业四第一关：把 Ollama 接到 DSH¶

    在 llm-pi-ai 里新增一个 openai-completions provider

    • 安装：解压 ollama-linux-amd64.tar.zst 到用户目录，不需要 root
    • ollama pull qwen3-coder:30b
    • provider 指向本地 /v1 接口，用完整 profile 让 agent 写脚本并运行

    作业四第一关，把 Ollama 接到 DSH 上。安装包解压到用户目录就能用，不需要 root。拉取 Qwen3 Coder 三十 B 模型，然后在 DSH 的 llm pi ai 里新增一个 provider，指向本地接口，让 agent 写一个脚本并运行。

    要点

    看起来一切正常……

    然后，agent 只回了一句话¶

    Hello! How can I assist you today?

    —— assignment4/README.md，L1 第 3 步（M0 实测现象）

    结果，agent 只回了一句：你好，有什么可以帮你的吗？没有报错，没有工具调用，就好像根本没看到你的任务。

    要点

    没有报错，也没有执行任何工具

    原因：默认上下文约 2k token¶

    Ollama 日志：truncating input prompt limit=2050 prompt=9158

    实际提示     系统提示 + 工具定义（约 9k token） | 用户任务
模型看到     被截断后的约 2k token

    答案在 Ollama 的日志里。Ollama 默认上下文只有约两千 token，而 DSH 完整配置的系统提示加工具定义就有约九千 token。Ollama 直接截断了输入，用户消息被截掉。模型没看到任务，只好打个招呼。

    要点

    用户消息被截掉了，模型只能打招呼

    修复与教训¶

    • 设置 OLLAMA_CONTEXT_LENGTH=32768 后，两轮对话都正确，用时约 18 秒
    • 静默截断最危险：不报错，只是结果变差
    • 接入任何推理服务，先核对上下文长度和实际 prompt token 数
    • 这也是作业四主体用 llama-server 的原因

    修复很简单，把 OLLAMA CONTEXT LENGTH 设成三万两千七百六十八，两轮对话就都正确了。教训更重要：静默截断不会报错，只会让结果变差。接入任何推理服务，都要先核对上下文长度，确认实际处理的提示 token 数。

    要点

    默认值不可信，日志要看

    小结¶

    • Ollama 入门快，llama-server 参数可控
    • GGUF：单文件模型，文件名标量化档位
    • Ollama 默认上下文约 2k，DSH 提示约 9k → 静默截断
    • 修复：OLLAMA_CONTEXT_LENGTH=32768

    小结一下。Ollama 适合入门，llama server 适合实验。默认上下文太短会导致静默截断，一定要看日志。下一讲，我们讲批处理与调度。
