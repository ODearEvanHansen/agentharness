    第 8 讲 · 评测¶

    SWE-bench、Verified 子集、官方 harness、数据污染与难题集

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第八讲，我们讲评测。没有可靠的评测，所有优化都只是感觉。本视频由程序合成，配音来自 DeepSeek 语音合成。

    SWE-bench：用真实 issue 考 agent¶

    • 题目来自 GitHub 上真实 Python 仓库的 issue
    • agent 拿到仓库和 issue 描述，产出一个补丁
    • 评测：应用补丁，跑隐藏的测试，看该过的测试是否通过
    • Verified：经过人工筛选、描述清楚可解的子集，带难度标注

    SWE bench 的题目来自 GitHub 上真实 Python 仓库的 issue。agent 拿到仓库和问题描述，产出一个补丁。评测时把补丁打上，运行隐藏的测试，看应该通过的测试是否通过。Verified 是经过人工筛选、描述清晰可解的子集，并且标注了预计的修复耗时。关键在于：判分看测试，而不是看 agent 自己说完成了。

    要点

    判分看测试，而不是看 agent 自己说完成了

    课程的 20 题基线¶

    M0 第 5 步，种子 2680 分层抽样

    • <15 min 10 题，15 min–1 h 8 题，1–4 h 2 题
    • 覆盖 9 个仓库，每个仓库最多 3 题
    • deepseek-flash，3 路并发，每题限时 20 分钟
    • 20 题、3 路并发约需 40 分钟

    课程的基线题集是从 Verified 里分层抽样的二十道题：十五分钟以内的十道，十五分钟到一小时的八道，一到四小时的两道，覆盖九个仓库，每个仓库最多三道。模型用 deepseek flash，三路并发，每题限时二十分钟，跑完一轮大约四十分钟。

    要点

    分层抽样：难度分布和仓库分布都要可控

    官方 harness 与踩坑¶

    swebench 5.0.2

    • 每题一个预构建镜像 sweb.eval.x86_64.
    • 数据集名必须写 SWE-bench/SWE-bench_Verified，旧名会 KeyError
    • 镜像每个约 3GB，20 题约 60GB，国内需要镜像源
    • agent 运行时长尾明显：必须设每题超时

    判分用官方的 swebench harness，五点零点二版。每道题有一个预构建的 Docker 镜像。M0 踩过几个坑：数据集名必须写新的 SWE bench 斜杠 SWE bench Verified，用旧名会因为缺字段报错；每个镜像大约三 G，二十题合计约六十 G，国内学员需要镜像源；agent 的耗时长尾明显，最长的一题约八分钟，评测脚本一定要设超时。

    要点

    用官方 harness 判分，结果才能和别人比较

    解决率：原 20 题接近饱和¶

    deepseek-flash，官方评测

    项目 数值
    自写 loop · 原 20 题 18 / 20
    DSH · 原 20 题 17 / 20
    自写 loop · 难题集 10 / 20
    DSH · 难题集 8 / 20

    结果是这样的。原二十题上，自写 loop 解决十八道，DSH 解决十七道，已经接近饱和，作业的排行榜会缺乏区分度。换成难题集，也就是 Verified 中一到四小时和四小时以上的二十道题，两边降到十道和八道，差距拉开了。

    要点

    题太简单，排行榜就没有区分度

    为什么分数这么高：数据污染¶

    M0 给出的三种可能

    • flash 本身很强
    • 抽到的题偏简单
    • Verified 是公开题集，可能进入了模型训练数据
    • 对策：用更难或更新的题，或改成「固定解决率比成本」的效率赛道

    为什么分数这么高？可能有三个原因：flash 本身很强；抽到的题偏简单；还有一个评测里绕不开的问题，数据污染。Verified 是公开题集，题目和标准答案可能已经进入了模型的训练数据。对策是使用更难或更新的题，或者干脆改成效率赛道，在固定解决率下比成本和耗时。

    要点

    公开基准的高分，不一定代表真实能力

    难题集的真实运行日志¶

    M0 困难集 runner 输出（节选）

    $ python run_swe.py loop,dsh 3   # M0 hard set, 20 tasks x 2 agents
loop django__django-10554                       247.4s req= 60 tools= 60 $0.056254  patch=   0 err=None
loop django__django-11885                       337.3s req= 60 tools= 65 $0.079887  patch=  41 err=None
dsh  django__django-10554                       365.4s req= 68 tools= 67 $0.086062  patch=  13 err=None
loop django__django-12325                        33.1s req= 12 tools= 17 $0.005867  patch=  13 err=None
dsh  django__django-11885                       146.3s req= 29 tools= 28 $0.036837  patch=  52 err=None
dsh  django__django-12325                        75.7s req= 23 tools= 22 $0.014035  patch=  17 err=None

    这是难题集的真实运行日志。可以看到，有的题目 loop 跑满了六十次请求，有一题甚至没有产出补丁；同一道题，两个 agent 的耗时和成本也差别很大。难题集每题平均成本大约是原题集的两倍，全集跑一轮约零点八美元，学员完全能够承受，所以它被选作作业三解决率赛道的题集。

    要点

    每题成本约是原 20 题的 2 倍，全集一轮约 $0.8

    小结¶

    • SWE-bench：真实 issue，按隐藏测试判分
    • 用官方 harness，注意数据集名和镜像体积
    • 原 20 题 18/17 接近饱和，难题集 10/8
    • 警惕数据污染，选有区分度的题集

    小结一下。SWE bench 用真实 issue 和隐藏测试判分；要用官方 harness，注意数据集名和镜像体积；原二十题已接近饱和，难题集才有区分度；还要警惕数据污染。课后请挑三道题，分别跑两个 agent 并用官方 harness 判分。下一讲，我们讲评测基础设施。
