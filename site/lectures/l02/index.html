    第 2 讲 · DeepSeek API 入门¶

    Chat Completions、工具调用、思考模式与前缀缓存计价

    视频制作中

    本讲视频将发布在 B 站，届时在这里嵌入播放。下面是讲稿正文。

    第二讲，我们来认识 DeepSeek API。它是整门课所有 agent 的发动机。我们会讲接口格式、工具调用、思考模式，以及决定成本的前缀缓存。本视频由程序合成，配音来自 DeepSeek 语音合成。

    Chat Completions：一次请求长什么样¶

    OpenAI 兼容格式，POST /chat/completions

    • messages：system、user、assistant、tool 四种角色按顺序排列
    • tools：用 JSON Schema 描述每个工具的名字和参数
    • 返回 choices[0].message：文本，或者 tool_calls
    • 返回 usage：输入、输出、缓存命中与未命中的 token 数

    DeepSeek 的接口和 OpenAI 格式兼容。一次请求主要包含两样东西：messages，也就是按顺序排列的对话历史；以及 tools，用 JSON Schema 描述模型可以调用的工具。返回结果里，模型要么给出文本，要么给出工具调用，另外还有 usage 字段记录用了多少 token。要记住，API 是无状态的，每一次请求都要把完整的历史重新发一遍。

    要点

    API 是无状态的：每次都要把完整历史发过去

    真实输出：一次工具调用¶

    给模型一个 get_time 工具，问它现在几点

    $ python3 toolcall_demo.py   # POST /chat/completions, tools=[get_time]
finish_reason: tool_calls
reasoning_content: …
tool_call: get_time {"tz": "Asia/Shanghai"}
usage: {"prompt_tokens": 293, "completion_tokens": 41, "prompt_cache_hit_tokens": 0, "prompt_cache_miss_tokens": 293}

    这是课程组实际调用的一次输出。我们给模型一个 get time 工具。模型没有直接回答，而是返回 finish reason 等于 tool calls，并给出要调用的工具和参数，时区是上海。注意，模型自己并不执行工具，执行是你的代码的事。usage 里这次输入两百九十三个 token，全部没有命中缓存。

    要点

    模型不执行工具，只说「我要调用什么、参数是什么」

    思考模式与 reasoning_content¶

    最容易踩的坑

    • 开启思考后，回复里多一个 reasoning_content 字段
    • 带 tool_calls 的 assistant 消息，要原样带回 reasoning_content
    • 漏掉它，下一次请求会直接报 400
    • 每个 tool_call_id 都必须有对应的 tool 消息

    DeepSeek 支持思考模式。开启后，回复里会多一个 reasoning content 字段，装着模型的思考过程。这里有一个最容易踩的坑：如果这条 assistant 消息带有工具调用，下一次请求时必须把 reasoning content 原样带回去，否则接口会报四百错误。同样，每一个工具调用的编号，都必须有一条对应的 tool 消息。

    要点

    作业二 handout 专门提醒：回传 reasoning_content

    计价：命中与未命中相差 50 倍¶

    deepseek-flash 高峰价，美元 / 百万 token（tools/usage_cost.py）

    项目 数值
    缓存命中输入 $0.006
    未命中输入 $0.30
    输出 $1.2

    再看计价。以 deepseek flash 的高峰价为例，每百万 token，命中缓存的输入只要零点零零六美元，未命中的输入是零点三美元，输出是一点二美元。命中和未命中相差整整五十倍。所以 agent 的成本，很大程度上取决于缓存命中率。

    要点

    同样的输入，命中缓存只要五十分之一的价格

    前缀缓存：只认开头完全相同的部分¶

    agent 天然适合缓存

    • 缓存按前缀匹配：从第一个 token 开始逐个比较
    • agent 每一步只在末尾追加，前面的历史都能命中
    • M0 实测：SWE-bench 上缓存命中率 96–97%
    • 但每一步都改开头（比如写入当前时间），缓存就全部失效

    前缀缓存只认开头完全相同的部分。agent 每一步只是在对话末尾追加内容，前面的历史保持不变，所以天然适合缓存。课程的 M0 实测中，在 SWE bench 上缓存命中率达到百分之九十六到九十七。但如果你每一步都去改开头，比如在系统提示里写入当前时间，缓存就会整体失效。这一点我们在第十二讲会详细展开。

    要点

    保持前缀稳定，是省钱的第一原则

    高峰价与低峰价¶

    高峰价

    • flash 未命中输入 $0.30 / M
    • flash 输出 $1.2 / M
    • 课程统一按高峰价报告成本

    低峰价

    • 价格减半：未命中 $0.15 / M
    • M0 原 20 题：DSH 高峰 $0.36，低峰 $0.18
    • 批量实验可以挑低峰时段跑

    DeepSeek 还有高峰价和低峰价，低峰时段价格减半。比如 M0 里 DSH 跑二十道题，按高峰价是零点三六美元，按低峰价是零点一八美元。大批量实验可以挑低峰时段跑，但在报告里比较不同方案时，课程统一按高峰价计算，避免时段带来偏差。

    要点

    比较方案时统一按高峰价，避免时段带来的偏差

    小结¶

    • API 无状态，每次发送完整历史
    • 工具调用由模型提出，由你的代码执行
    • 思考模式下要回传 reasoning_content
    • 命中与未命中相差 50 倍，保持前缀稳定

    小结一下。API 是无状态的；工具调用由模型提出，由你执行；思考模式下要回传 reasoning content；命中缓存和不命中相差五十倍。课后请自己发一次带工具的请求，连发两次，看看缓存命中有什么变化。下一讲，我们进入 DeepSeek Harness。
